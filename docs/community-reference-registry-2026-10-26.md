## 1. Niveaux de décision

- **SOCLE** : seuls les dépôts OEM [microduck](https://github.com/pollen-robotics/microduck), [microduck_rl](https://github.com/pollen-robotics/microduck_rl), [microduck_yocto](https://github.com/pollen-robotics/microduck_yocto) et notre dépôt (version `main` et pointeurs Git réellement épinglés) forment le socle de référence. `robotd`, `mediad`, `tofd`, les politiques et les contrats présents à la version examinée font foi ; un document de roadmap n'est pas du code.
- **VEILLE PRIORITAIRE** : une source pertinente **à consulter avant une nouvelle conception du chantier concerné**, mais **non intégrée** et dont le statut doit être revérifié.
- **VEILLE CONDITIONNELLE** : consulter seulement quand une fonctionnalité facultative ou un chantier suspendu est repris.
- **HORS PÉRIMÈTRE ACTUEL** : référence utile à connaître, mais non nécessaire pour décider R2.
- **CANDIDAT À INTÉGRATION** : **aucun** à l'issue de C3. Cela réclamera une PR distincte, licence fichier/poids, compatibilité de versions, tests, profilage et responsabilité moteur unique.

**Critères de comparaison appliqués :** fonction exacte et propriétaire, preuve `codé` vs `simulé` vs `mesuré sur machine réelle`, version/API, sécurité et confidentialité, coût ARM/RAM/énergie non inventé, licences, complémentarité vs doublon et effets sur R2.

## 4. Impact immédiat sur notre plan R2 et les instructions

### Travaux maintenant : aucun code externe à intégrer

1. **R2-B+1** : les mêmes bancs M1-A/M1-B/B2 ; corpus de **sons réellement réenregistrés**, provenance/licences, négatifs ressemblants, seuil de validation fixe, `unknown` et erreurs.

3. **R2-C / R2-D** : comparer les faux rapprochements et poursuivre la mémoire **mono-écrivain** avec garde-fous et mesures réelles SQLite sur hôte.
4. **En parallèle, sans code ni déploiement** : conserver les propositions #381/#414 sur le dépôt constructeur et les références communautaires dans ce registre. Avant tout chantier ultérieur : vérifier si la PR a fusionné, les versions et les fonctions effectives. **Ne pas retarder R2 pour créer une nouvelle stack de navigation, de dialogue ou de simulation.**

### Proposition pour les instructions permanentes (ne pas appliquer automatiquement)

Quand cette sélection aura été relue et fusionnée, ajouter un court principe aux consignes du projet, plutôt qu'une longue liste de dépôts ou de branches mouvantes :

> **Réutilisation et veille communautaire.** Avant tout nouveau chantier, comparer dans cet ordre : (1) code OEM **épinglé dans `upstream/`**, (2) état des évolutions et PR du constructeur, (3) code Companion déjà présent et ses tests, (4) références externes **pertinentes au chantier** dans `docs/community-reference-registry-2026-10-26.md`. Pour chaque option relever versions, licence des fichiers/poids, statut réel, mesures reproductibles, consommation de ressources, sécurité et risque de doublon. Une PR ouverte ou un résultat MuJoCo ne prouve ni une fonctionnalité OEM livrée ni une validation physique. Ne pas importer ni activer de code communautaire sans intégration ciblée, tests indépendants et conservation de `robotd` comme autorité motrice.

**À ne pas faire maintenant :** modifier les instructions personnalisées utilisateur sans revue finale, élargir la liste des dépôts de référence « officiels » à des projets tiers, copier le LLM qui pilote les moteurs, ou modifier le protocole R2 sans mesures.

## 5. Prochain point de révision

Revoir ce registre **au début de chaque chantier concerné** et lors d'une mise à jour OEM épinglée, non à chaque nouveau commit de la communauté. Tout changement de classement doit fournir : lien de code précis, commit/version, preuves et limites, effet sur notre architecture, choix `réutiliser / adapter / créer` et coût d'intégration. Garder cet historique dans les PR et rapprocher le registre de `AGENTS.md` / instructions personnalisées lorsque les décisions auront été validées.

**Clôture C3 :** registre et décisions documentaires ; aucun test ou banc nouveau lancé, aucune fonction externe déployée, aucun changement au contrôle constructeur ou à la mémoire, aucune preuve RK3566. Les essais communautaires restent attribués à leurs auteurs.
