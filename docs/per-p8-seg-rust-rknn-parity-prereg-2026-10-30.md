# PER-P8 — Porte de parité réelle Rust/ONNX avant raccord OEM (préenregistrement, 30 octobre 2026)

## Préalable et responsabilité

**Objectif V1 sans robot :** prouver que le noyau Rust P7 produit les **mêmes régions et masques** que le décodage Ultralytics officiel P6, lorsque les deux consomment **exactement les mêmes** sorties du simulateur RKNN 2.3.2 ciblant le RK3566. Aucune inférence moteur, aucune caméra supplémentaire, aucune modification du code fournisseur ou des gitlinks. Résultat attendu = preuve de **cohérence logicielle sur PC**, pas capacité de segmentation fiable, mémoire visuelle ou débit 2 Hz sur carte.

Base : PR **#217 ouverte, non fusionnée**, HEAD initial `fae43f03f66e47ea16c592228949e033210dd0bf`; la PR P8 est **dépendante** de #217 et n'est pas fusionnable indépendamment avant elle. Gitlinks OEM `microduck@942e58e3aa6dbb28e7037203fff11866122c7567` et `microduck_rl@b02fdea4902c2b93b7d34a83a6f05da4ececb7d3` inchangés ; OEM main différent. #216 P6 fusionnée ; sur l'unique JPEG Rockchip `000000005001.jpg` (calibration, déjà vue), le tail d'ONNX Runtime sur CPU PC donne 10 masques non vides à partir du simulateur RKNN. **Manque prouvé** : P7 n'a jamais été comparée à ces vrais tenseurs quantifiés ; ses 7 tests Rust sont des fixtures synthétiques et ne prouvent pas la parité.

## Réemploi / essai limité

Réutiliser `experiments/per_p6_yolo26seg_tail.py` (versions, provenance, un modèle `yolo26n-seg.pt` SHA256 `361fbfabab285c3237700b6bb91d7ecfa602cd945fffda8dbe1242829b71e73f`, `ultralytics==8.4.192`, toolkit `rknn-toolkit2==2.3.2`, calibration COCO 20 images Rockchip 837db8e, `imgsz=640`, ONNX opset 19, INT8, 1 simulation sur même instance). Ajouter un **hook de comparaison facultatif après les mêmes dix sorties simulées**, pas de second passage RKNN. Créer un exécutable Rust **hôte de test** du crate P7 qui lit localement les deux tableaux de `float32` little-endian `[1,300,38]` et `[1,32,160,160]`, appelle `kwipi_seg_mask_core::decode`, renvoie ses masques 160² dans un fichier temporaire, sans réseau ni moteur. Le Python de comparaison reconstruit les masques **officiels** `ultralytics.utils.nms.non_max_suppression(end2end=True, conf=0.25, max_det=10)` puis `ops.process_mask(upsample=False)` et compare masque/score/classe/boîte. Écriture **uniquement** dans `RUNNER_TEMP`, pas de poids, images, masques ou tenseurs téléversés ; **statistiques JSON seulement**. Le protocole demande une vraie inférence déjà justifiée P6, **pas de nouvelles photos**.

## Critères positifs/négatifs fixés avant résultats

1. **Témoins CPU synthétiques** : Rust P7 et la référence produisent un rectangle et masque cohérents depuis un jeu factice à deux classes ; tests Rust existants de score/NaN, boîtes invalides, tensors hors dimensions, borne dix masques restent verts. Une entrée binaire tronquée, répertoire non temporaire, score non fini ou masque absent doit **échouer explicitement** sans aucune substitution.
2. **Témoin réel unique (réemploi P6)** : Rust doit retourner **le même nombre de candidats** que la NMS officielle (`0..10`, sans forcer les détections), **même ordre, mêmes classes**, écarts max sur score/xyxy **≤1e-3**. Tous les masques [160,160] binaires 0/1, aucune case hors boîte, aucune valeur NaN/inf. Pour au moins 1 objet, masque non vide requis pour établir une parité observable ; sinon résultat `insufficient_zero_masks`, sans succès.
3. **Seuil de parité de pixel**, pour éviter d'inventer l'égalité bit-à-bit de deux implémentations f32 : **≥99,9 % de tous les pixels** comparés et **≥99,5 % par instance**. Aucun seuil changé après les chiffres. Publier nombre exact de pixels différents, minimum par instance, total et temps d'exécution PC Rust **séparés** de l'inférence simulateur. Si des différences dépassent le seuil, **échec et STOP**, conserver erreur et cause (géométrie, seuil, indices, quantification) ; pas de modification du modèle, SDK, calibration ou retraitement de cette image.
4. **Confidentialité et sûreté** : inférence sur un seul cliché public déjà fixé ; aucun fichier modèle/tenseur/JPEG/mask publié, aucun upload privé, jamais SQLite, caméra ni moteur. **Licence Ultralytics AGPL/Enterprise sur les poids et possible modèle dérivé non résolue : pas de distribution/installation**.
5. **Portée de la décision** : si parité et CI vertes, conclusion `rust_cpu_matches_vendor_host_sdk_on_one_calibration_image` seulement ; cela débloque un **futur raccord du noyau dans le chemin `mediad` OEM**, à tester sur copie de staging épinglée, sans changer le submodule ni présumer ressources et 2 Hz du RK3566 réel. Si non, conserver P7 en prototype fixtures et corriger seulement un défaut indépendant démontré.

## Statuts retenus

- Prévu/codé/testé Rust fixtures ≠ parité mesurée ≠ simulé RKNN ≠ intégration OEM ≠ code V1 déployable ≠ validé robot.
- Le robot physique **ne sera pas acheté avant préparation de la V1** ; les tests réels sont donc un jalon d'intégration/optimisation ultérieur et **ne doivent pas bloquer** les sous-tâches logiciel, SDK et Yocto faisables sur PC.
- Ne pas fusionner P8 tant que P7 est non fusionnée ou que la CI pertinente n'est pas verte, ni retargeter sans vérifier le nouveau SHA main/PR.

## Amendement de contrat pré-essai, lié à la source fournisseur (30/10/2026)

L'inspection du [NMS officiel `ultralytics==8.4.192`](https://github.com/ultralytics/ultralytics/blob/v8.4.192/ultralytics/utils/nms.py) révèle une erreur de l'implémentation P7 initiale : l'option `end2end=True` **ne trie pas par confiance** ; elle conserve **les premières lignes** `score > conf_thres` dans l'ordre de `pred`, limitées à `max_det`. Le noyau Rust P7 et la branche dépendante P8 sont corrigés avant l'essai de parité des sorties réelles du simulateur. Un test de contrôle à deux lignes de scores croissants (0,61 puis 0,99) est ajouté, il exige l'ordre original et la parité avec le fournisseur. Aucun critère numérique de parité (99,9 % global, 99,5 % par masque), seuil, poids, calibration ou inférence additionnelle n'est changé. Si le test P8 avait déjà démarré, son résultat de l'ancien SHA reste distinct et ne vaut pas validation de la correction.
